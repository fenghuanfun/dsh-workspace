# 源目录

DSH 的一个工作区只拥有一个目录（工作区注册表里的 `path`，也是会话的 `cwd`）。这个插件为**同一个工作区**追加额外的源目录，不改动那条注册记录：原目录仍在，追加的目录与它并列，共同作为该工作区的源，且**权限与策略和原目录一致**。

## 用法

1. 在侧边栏工作区行上点「…」或右键，选 **源目录**。
2. **添加** 打开系统目录选择器；每行可用 **移除** 删除。
3. **保存** 后立即对当前工作区的会话生效。

没有改动时 **保存** 禁用；读取失败时只提供 **重试**，不会提交空列表。

## 行为

- 保存后，该工作区**已开启的会话**立即获得每个目录的会话级可写授权（与工作区目录同策略），并在运行时上下文里看到一行提示：这些目录同样属于本工作区。
- 相对路径、`bash` 的默认 `cwd`、右侧文件树仍以工作区目录为准。
- 读取与写入受当前权限模式约束（只读模式下仍只读）。

## 校验规则

- 只接受**绝对路径**，且必须是**已存在的目录**；路径经 `realpath` 规范化后落盘。
- 工作区目录自身会被忽略；已被某个已选目录包含的子目录自动折叠。
- 每个工作区最多 32 个附加目录；列表为空即删除该工作区的记录。

## 存储

`$DSH_HOME/storages/dsh-workspace.json`（默认 `~/.dsh/storages/dsh-workspace.json`），按规范化后的工作区路径存放。写入使用临时文件加 `rename` 的原子替换；写盘失败不会先改内存。

## 限制

- 附加目录不参与相对路径解析，也不进入 `bash` 的默认 `cwd`。
- 右侧「文件」面板的文件树仍只列工作区目录。
- 授权是会话级运行时状态：会话 resume / fork 后由本插件重新登记；插件停用后授权消失。
- 该操作只对用户开放，模型不能自行增删工作区源目录（属于权限授予）。
